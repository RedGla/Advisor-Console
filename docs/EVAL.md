## Eval Script — Bugs Fixed

The original `eval/run_eval.py` had two bugs that would cause every run to fail:

1. **Wrong auth flow** — `login()` expected an `access_token` in the response body
   (Bearer auth), but the API uses **session cookies** (`session_user_id`).
   Fixed: `requests.Session` now carries the cookie automatically.

2. **Missing conversation creation** — the script posted to
   `/conversations/{prompt_id}/messages` directly, but those conversations
   didn't exist → every request returned 404.
   Fixed: script now creates one conversation per eval run, then sends all
   prompts into it.

3. **Wrong response shape** — the endpoint returns the assistant `Message`
   object directly (`{"content": ..., "prompt_tokens": ...}`), not a nested
   `{"message": {"content": ...}, "usage": {...}}` dict.
   Fixed: response parsing aligned with the real API shape.

## Known Limitations

The following limitations are acknowledged in the PRD itself and are **out of scope** for the current sprint:

1. **Naive keyword grounding** — document retrieval is keyword/BM25-based. Semantic similarity (embeddings / vector search) is not implemented. This can cause relevant passages to be missed when the user's wording differs from the source text.

2. **No embeddings** — there is no embedding pipeline or vector store. Retrieval quality is therefore bounded by exact-term overlap, and synonyms or paraphrases may fail to surface the correct context.

> These limitations are tracked as future work. No score deduction is applied to rubric criteria 1 or 2 solely because of these two gaps, provided the system behaves correctly within its stated keyword-retrieval approach.
